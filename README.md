# 렌트카 예약 시스템으로 배우는 대규모 트래픽 대응

차량 검색부터 예약, 결제, 취소·환불, 대여, 반납까지 이어지는 렌트카 서비스를 단계별로 구현하는 프로젝트다. 기본 기능을 먼저 완성하고, 트래픽이 늘어날 때 나타나는 병목과 동시성 문제를 측정한 뒤 개선한다.

## 시리즈 소개

- 차량 검색부터 반납까지 작은 렌트카 서비스의 핵심 흐름을 구현한다.
- PostgreSQL 예약 처리에서 발생하는 검색 지연과 중복 예약 문제를 다룬다.
- Redis 캐시, RabbitMQ 비동기 처리, Prometheus·Grafana 모니터링을 단계적으로 적용한다.
- 결제와 환불은 실제 결제사를 연동하지 않고, 지연이 있는 시뮬레이션으로 처리 결과를 데이터베이스에 기록한다.

## 기술 구성

| 영역 | 기술 |
|---|---|
| 애플리케이션 | Java 21, Spring Boot 4 |
| 웹 화면 | Thymeleaf |
| 데이터베이스 | PostgreSQL 18 |
| 캐시 | Redis |
| 메시징 | RabbitMQ |
| 모니터링 | Spring Boot Actuator, Micrometer, Prometheus, Grafana |

Redis, RabbitMQ, Prometheus, Grafana는 기본 기능을 구현한 뒤 관련 회차에서 추가한다.

## 현재 범위

- 차량 목록·상세 조회와 대여 기간별 예약 가능 차량 검색
- 예약 생성·조회·취소
- 랜덤 지연을 포함한 결제·환불 시뮬레이션 및 결과 저장
- 대여 시작과 반납 완료 처리
- 부하 측정, 검색 성능 개선, 동시 예약 제어

회원가입, 실제 결제사 연동, 보험, 지점 간 차량 이동, 복잡한 요금·환불 정책은 초기 범위에서 제외한다.

## 예약 규칙

- 날짜 단위 대여를 기준으로 한다.
- 대여 시작일은 반납 예정일보다 빨라야 한다.
- 같은 차량의 사용 기간이 겹치는 예약은 허용하지 않는다.
- 예약 상태는 `RESERVED`, `RENTING`, `COMPLETED`, `CANCELED`로 관리한다.
- 결제와 환불 상태는 예약 상태와 분리해 기록한다.
- 대여 시작 전 예약을 취소할 수 있으며, 결제가 완료된 경우 환불을 처리한다.

세부 규칙과 개발 환경은 각 회차 문서에서 정리한다.
